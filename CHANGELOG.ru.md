## v2.45 — статика камер: альфа задаётся событием, а не сериализованным coeff 100

Перекрёстная проверка: титульный «blip flash 2» в игре 95% прозрачный, хотя в данных объекта непрозрачный — это объясняется только событийной установкой альфы (тот же act #65).

- **Громкая диагностика**: `XContent: user=N create=0x… disp=0x…` и `XContent: flush=0x… close=0x…` в дебаггер-логе (0 = OK).

## v2.38 — фолбэк хранилища: XContent сдох ⇒ обычные файлы на HDD (фикс «игра с нуля после game over» + «ACH save FAILED»)

- **Причина (логи реальной консоли)**: XContent-хранилище системной сборки на этом RGH нерабочее (нет подписанного профиля) — `ACH save FAILED`, и — хуже — сейв после 6 AM молча не писался, поэтому любая смерть/game over (вкл. дев-скример) шла через `RefreshMenuFromProgress` → `Progress::Load` → чтение падало → тайтл показывал игру с нуля. Ровно тот баг.

Папка фолбэка намеренно отличается от `game:\save\` (хранилище Live Safe + кандидат импорта), чтобы бут не предлагал импортировать наш собственный сейв. Live Safe не тронут.
- Эффект: перечитывание сейва после game over работает везде; `ACH save FAILED` на RGH заменяется реальной записью; ачивки локально персистятся (профильная запись `XUserWriteAchievements` — отдельно, для списка в Guide всё ещё нужен SPA).

## v2.34 — окна сообщений: watchdog + программный фолбэк (фикс «звук есть, окна нет»)

- **Причина (тест импорта на реальной консоли)**: `XShowMessageBoxUI` сыграл звук, но окно не нарисовалось — вызов происходит на буте до первого представленного кадра, а дока гарантируют только громкий сбой через `ERROR_ACCESS_DENIED` (когда системный UI уже занят); тихо не отрисовавшееся/зависшее окно оставляет прежний `while(!XHasOverlappedIoCompleted) Sleep(16)` висеть вечно.

## v2.29 — стриминговый загрузчик пака (под Sister Location)

- **`PakLoader::LoadStreaming()`** — «скольжение по файлу»: резидентны только заголовок + таблицы + пул имён (десятки КБ); блоб каждого ассета читается по смещению из таблицы при первом обращении. Текстуры заливаются в D3D при первом `FindTexture`, стейджинг сразу освобождается (UMA: дальше они живут в общем пуле 512 МБ); звуки читаются и нормализуются персонально при первом `FindSound` (RIFF-распаковка / 8-бит / порядок байт — вместо голосования по всему банку **мини-голосование на старте** по 4 КБ-окнам нескольких звуков; passthrough-блобы вроде mp3 у SL честно помечаются неиграбельными вместо мусорного PCM).
- **`PreloadAsync(names, count)`** — фоновый воркер (XDK: `CreateThread` + event + критическая секция; на PC — синхронный фолбэк) выполняет ту же предзагрузку заранее, чтобы переход комната→комната подтягивал текстуры следующей комнаты во время отрисовки текущего кадра. Промах `FindTexture` всё равно грузит синхронно — рендер никогда не увидит недогруженную текстуру.
- **Скуп (решение): только SL.** FNAF1/2/3/4 остаются на жадном `Load()` — их паки спокойно помещаются в пул 512 МБ; жадный путь отрефакторен (`UploadTexture` вынесен), но поведение идентично. SL-модуль (stage 7) загрузится через `LoadStreaming` и поведёт `PreloadAsync` от своих переходов комната-фрейм. До тех пор код спит — FNAF1 грузится ровно как раньше.
- **Мягкий скан паков на старте (`AppRegistry_ScanPaks`)**: проверяет пак каждого модуля (`game:\<PakName>`, проба fopen — только чтение), печатает по строке OK/not-found в лог и на экранный консоль, и ставит активным модуль, чей пак существует — FNAF1 в приоритете, далее первый найденный. Отсутствующие паки никогда не валят старт: при одном `fnaf1.pak` игра запускает FNAF1 ровно как раньше, а при пустом наборе как обычно ругается существующее окно «missing pak». Сам пак грузится по `PakName()` активного модуля вместо захардкоженного имени.
- Обоснование по докам XDK (см. docs/ARCHITECTURE.md): игры идут с **HDD**, поэтому `XFileCache` / `ReadFileScatter` / физические ключи сортировки (всё — только для DVD) не применимы; правильная примитив — обычные seek+read по открытому файлу.
