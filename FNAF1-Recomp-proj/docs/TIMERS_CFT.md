# Таймеры CFT-рантайма — единицы, семантика, таблицы (v2.72-эра)

Источник: события из декомп-дампов (`Dumps/<Game>/Events/frame_*.txt`, суть — сырые
данные оригинальных экзешников). Полные таблицы «кадр → условие → ms» лежат рядом:
`docs/t2_<игра>.tsv` (пробел = разделитель; второй столбец `-7`/`-8` — тип условия).

## Вердикт по единицам: миллисекунды

Значение параметра `timer N` (тип параметра 2/42, `Parameter::Kind::Time`) хранится
в **миллисекундах**. Аннотация `(~Xs)`, которую ctfak печатал до правки, делила на 50
(вера «1/50 с тик» из отображения редактора `1"50`) и врала ровно в 20 раз.

Доказательная цепочка (сырые значения из событий самих игр):

| Якорь | Сырое значение | Реальность |
|---|---|---|
| F1 офис, интервалы ИИ (группы 188-191) | 4970 / 4980 / 3020 / 5010 | канонические 4.97 / 4.98 / 3.02 / 5.01 с (Бонни/Чика/Фредди/Фокси) — тики дали бы 99.4/99.6/60.4/100.2 с, игра была бы мёртвой |
| F4 «level», час ночи | 60000 | 60 с/час (портировано и подтверждено на оригинале; 1200 с — неиграбельно) |
| F3 офис, час ночи 1 / далее | 40000 / 60000 | 40 с / 60 с (портировано 1:1) |
| F1 died/gameover, холд | 10000 | 10 с (портировано) |
| F2 dream, Robot / staticend2 | 30000 / 32000 | 30 с / 32 с (портировано) |
| F1 офис, robotvoice camp replay | 300000 | 300 с (портировано) |

**Правка тула**: `EventsListing.cpp::ticksToSeconds` теперь делит на 1000 (комментарий
с доказательствами внутри); пересобрано, ctfak-tests 39/39. Существующие дампы НЕ
перегенерировались — у них важны сырые значения, они не менялись.

## Семантика двух типов условий (объект Timer, type −4)

- **`cond #-7` — «Timer reaches N»**: одноразовый. Срабатывает один раз, когда таймер
  группы доходит до N. Типичный холд экрана: died 10000, ad 5000, dream 30000.
- **`cond #-8` — «Every N»**: периодический. Срабатывает каждые N мс, пока группа
  активна (ре-арм не нужен). Типичные ре-роллы: static alpha 90, blackout ramp 110,
  интервалы ИИ 4970/5030/3020/5010, час 60000.

В дампах оба печатались одинаково («ON Timer»), различие — только в номере условия.

## Сверка с портом: найденные расхождения (значения = дамп)

Портированная конвенция «timer N = raw ms» подтверждена. Но три места были вживлены
в эпоху веры в ÷50-аннотацию и стоят в 20 раз дольше дампа:

| Место | Дамп | Порт было → стало (v2.72, 1:1) |
|---|---|---|
| F1/F2 титул, static alpha ре-ролл (Every) | **90 ms** | 1.8 с → **90 ms** |
| F1/F2 титул, лампа: варианты (Every) | F1 **80 ms** / F2 **100 ms**, строго 97/98/99 (F2: 0/1/2 из R(50)) | 1.6 с + гейты 85/93/98 → дамп-гейты |
| F1/F2 титул, альфа бэка R(250) (Every) | **300 ms** | 6 с → **300 ms** |
| F1/F2 титул, окно blip-бэнда (Every) | **300 ms** | 6 с → **300 ms** |
| F1/F2 титул, альфа бэнда (Every) | F1 100+R(100)/**80 ms**, F2 200+R(50)/**100 ms** | 1.6/2 с → дамп |
| F3 титул, static (Every/бёрст) | бёрст каждые **2000 ms** (25+R(3), −2/кадр ≈ 0.22 с), альфа 200+R(100) каждые **40 ms** | 8%-вспышки 1.6-с слотов непрозрачно → дамп |
| F1 ad, авто-переход (Reach) | **5000 ms** | ~8 с → **5 s** |
| F2 ad, авто-переход (Reach) | **9000 ms** | 90 с → **9 s** |
| F3 ad, авто-переход (Reach) | 9000 ms | 9 с ✓ (уже совпадало) |

Титульные «исключения 1.8/6 с» из старых заметок = та же отравленная аннотация;
валидация юзера касалась ДИАПАЗОНА альфы (выглядит), а не частоты ре-ролла.
Статус: **вжито 1:1 в v2.72** (правки юзер подтвердил: «давай 1 к 1 пока что»).

Всё остальное, что сверено, сходится 1:1 (кампания v2.53 «×20-cadence fixes»,
blackout 110 мс, часы, холды экранов).

## Как пользоваться

1. Нужен тайминг экрана/поведение → смотри t2_<игра>.tsv: строка = кадр, тип
   (−7 reach / −8 every), ms.
2. «Every» = период, пока группа активна; «Reach» = одноразовый холд от активации.
3. Единицы — ms, всегда. Аннотацию `(~Xs)` в старых дампах игнорировать (она ×20).
4. Правило проекта «timers = raw ms» подтверждено полностью; «исключений» больше нет.
